# CL-311: Keep the whole stack and only the PR's own commits in pr sync

## Goal

`pr sync` on any PR of a stack keeps the whole stack linked, and replays only that PR's own commits.

## Context

On 2026-10-31, in the stack 108 -> 109 -> 111:

- `pr sync 109` failed at `gh stack link 108 109 --open` with "this would remove #111 from the stack". `pr open` linked only the PRs below, so a PR in the middle dropped the ones above it.
- `pr sync 111` then replayed commits from other PRs, starting with "chore(tracker): start CL-204". #109 had been rebased in another clone, so this clone had no fork point recorded for #111, and a plain rebase replayed #109's old commits.

## Steps

1. Branch `clutch/cl-311-sync-stack`.
2. In `pr open`, link the PRs below, the PR itself, and the PRs above it (`stackAbove`).
3. In `pr sync`, find the fork point in this order: the point recorded in this clone, `git merge-base --fork-point` from the base's reflog, then the base PR's heads before each force push, from GitHub's `HeadRefForcePushedEvent`s. Use the first one the branch contains.
4. Test both cases.

## Files

- `tools/github/pr.ts`, `tools/github/branch.ts`, `tools/github/stack.ts`, `tools/github/github.ts`
- `tools/github/sync.test.ts`

## Acceptance criteria

- `pr sync` on a middle PR runs `gh stack link` with every PR of the stack.
- Without a recorded point, `pr sync` rebases `--onto` the base PR's head from before its force push.
